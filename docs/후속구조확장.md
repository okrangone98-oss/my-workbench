# 후속구조확장

## 1. 확장 원칙

- 초기에는 docs 중심 최소 구조를 유지한다.
- 실제 재사용 수요가 확인될 때만 폴더를 추가한다.
- 폴더 추가 시 목적, 포함 자산, 제외 자산을 함께 문서화한다.

## 2. 단계별 확장안

### Phase 0 (현재)

- README.md
- docs/

### Phase 1 (문서/운영 안정화 이후)

- prompts/: 재사용 프롬프트
- templates/: 반복 양식
- workflows/: 업무 흐름 문서

진입 조건:
- 같은 형식의 문서/프롬프트가 3회 이상 반복 생성될 때

### Phase 2 (자동화/개발 본격화)

- automation/: 자동화 스크립트
- apps/: 실행 코드

진입 조건:
- 자동화 스크립트 또는 실행 코드가 실제 운영에 투입될 때

### Phase 3 (참고/보관 체계 분리)

- references/: 외부 참고 정리
- archive/: 보관용 자료

진입 조건:
- 운영 문서와 참고/보관 자료가 혼재되기 시작할 때

## 3. 제안 최종 구조(확장 완료 시)

- README.md
- docs/
- prompts/
- templates/
- apps/
- automation/
- workflows/
- references/
- archive/

## 4. 확장 체크리스트

- 폴더가 없어서 실제 작업이 막히는가?
- 신규 폴더에 들어갈 파일이 5개 이상인가?
- 기존 폴더로는 의미 구분이 어려운가?
- 보안/권한 분리가 필요한가?

모든 항목을 검토한 뒤 확장한다.
