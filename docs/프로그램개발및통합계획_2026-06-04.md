# 프로그램 개발 및 통합 계획

작성일: 2026-06-04

## 1. 개발 목표

`my-workbench`를 사용자가 로컬 컴퓨터에서 매일 쓰는 AI 업무본부로 만든다.

이 프로젝트의 핵심은 "AI가 모든 것을 자동으로 처리하는 프로그램"이 아니다. 사용자가 직접 판단하고 통제하면서, AI와 자동화가 반복 업무를 빠르게 도와주는 프로그램이다.

최종 목표:

- 한글 메뉴로 스킬을 고른다.
- 자료를 복사해서 붙여넣는다.
- 프로그램이 문제 구조, 질문, 초안, 체크리스트를 만든다.
- 사용자는 필요한 경우 ChatGPT, Claude, Gemini 같은 AI에 질문을 붙여넣는다.
- AI 답변을 다시 붙여넣으면 프로그램이 결과물을 정리한다.
- 중요한 자료는 로컬에 저장하고, GitHub에는 민감정보 없는 작업물만 백업한다.

## 2. 제품 원칙

### 2-1. 로컬 우선

기본 데이터는 로컬에 둔다.

- 원본 자료: `data/brain/00_raw`
- 정리된 지식: `data/brain/10_wiki`
- 진행 중인 프로젝트: `data/brain/20_projects`
- 업무 절차와 스킬: `data/brain/30_skills`
- 마케팅 자료: `data/marketing`
- 사업계획 자료: `data/planning`

### 2-2. 한글 메뉴 우선

사용자는 영어 명령어를 외우지 않는다.

기본 UX:

```text
무엇을 하시겠어요?

1. 정책 문제 구조화
2. 시민 서비스 개선
3. 사업계획서 도우미
4. 마케팅 콘텐츠 만들기
5. 자료 붙여넣고 정리하기
6. AI 답변 검토하기
```

내부 명령은 영어로 둬도 되지만, 사용자에게는 한글 메뉴와 쉬운 설명을 먼저 보여준다.

### 2-3. 수동+자동 하이브리드

자동화할 것:

- 자료 저장
- 요약
- 태그 제안
- AI 질문 생성
- 초안 조립
- 체크리스트 생성
- Git 변경사항 요약
- 안전한 dry-run 계획

사용자가 직접 확인할 것:

- 외부 AI에 보낼 내용
- 민감정보 포함 여부
- 최종 제출 문서
- 실제 파일 이동/삭제
- GitHub push
- 유료 API 사용

### 2-4. 무료/오픈소스 우선

우선순위:

1. Markdown, JSON, SQLite
2. TypeScript, Node.js, npm workspaces
3. 브라우저 기반 무료 도구
4. 사용자가 이미 쓰는 AI 서비스
5. 필요할 때만 유료 API

## 3. 통합 대상과 역할

### 3-1. my-workbench

역할: 본체.

담당:

- CLI
- core 로직
- 스킬 카탈로그
- 문서 허브
- 로컬 데이터 구조
- 안전한 GitHub 백업 흐름

### 3-2. connect-ai

역할: 로컬 세컨드브레인 철학 흡수.

가져올 것:

- raw 자료를 날짜별로 저장하는 구조
- raw에서 wiki로 정리하는 사고방식
- GitHub 동기화 전 안전 점검
- 로컬 우선 지식 저장소 구조

가져오지 않을 것:

- VS Code 확장 전체 구조
- 자동 force push 방식
- 사용자가 이해하기 어려운 자동 동작

### 3-3. planning-copilot

역할: 사업계획서/공고문 분석 워크플로우 흡수.

가져올 것:

- 공고문 분석
- 요구사항 추출
- 좋은 질문 생성
- 참고자료 모으기
- 사업계획서 초안 조립
- 제출 전 체크리스트

### 3-4. markter

역할: 마케팅 브레인 흡수.

가져올 것:

- 브랜드 위키
- 페르소나
- 콘텐츠 아이디어 생성
- 인스타/블로그/쇼츠 초안
- 성과 기록
- 잘 된 패턴 학습

### 3-5. antigravity-awesome-skills

역할: 스킬 참고 라이브러리.

가져올 것:

- 바로 쓸 수 있는 스킬 작성 방식
- 마케팅, 자동화, 메모리, 프롬프트 최적화 관련 일부 아이디어

가져오지 않을 것:

- 모든 스킬 전체 복사
- 사용자가 이해하기 어려운 전문 스킬
- 민감정보나 외부 연동이 강한 스킬

## 4. 개발 단계

### Phase 0. 기준 확정

상태: 진행 중.

목표:

- 프로젝트 방향 문서화
- 한글 메뉴/객관식 UX 원칙 확정
- 스킬 선택 메뉴의 첫 버전 구현

완료 기준:

- `skill:menu`로 한글 스킬 선택지가 보인다.
- 번호를 고르면 준비 자료, 결과물, AI 질문이 나온다.
- 문서 허브에서 개발 방향을 찾을 수 있다.

현재 완료된 것:

- `packages/core/src/skill-catalog.ts`
- `npm run dev:cli -- skill:menu`
- `docs/로컬AI업무본부_통합설계_2026-06-04.md`
- `docs/스킬사용성원칙_한글명령어_객관식.md`

### Phase 1. 로컬 자료 수집 엔진

목표:

사용자가 복사한 자료를 로컬에 안전하게 저장한다.

기능:

- `brain:capture`
- 자료 종류 선택
- 날짜별 raw 저장
- 제목 자동 생성
- 태그 입력 또는 추천
- AI에게 물어볼 질문 생성

한글 메뉴:

```text
자료를 어떻게 저장할까요?

1. 정책/민원 자료
2. 사업계획 자료
3. 마케팅 자료
4. 회의 메모
5. 그냥 보관할 자료
```

산출물:

- `data/brain/00_raw/YYYY-MM-DD/*.md`
- `data/brain/index.json`

### Phase 2. AI 질문 생성 엔진

목표:

사용자가 AI에게 좋은 질문을 던질 수 있게 한다.

기능:

- `ai:question`
- 목적 선택
- 질문 템플릿 적용
- 복사 가능한 프롬프트 생성
- 민감정보 경고

한글 메뉴:

```text
AI에게 무엇을 물어볼까요?

1. 문제 구조를 분석해줘
2. 사업계획 논리를 만들어줘
3. 시민 입장에서 불편한 점을 찾아줘
4. 콘텐츠 아이디어를 만들어줘
5. AI 답변을 검토해줘
```

산출물:

- 복사 가능한 AI 질문
- 질문 생성 기록
- 후속 확인 질문

## 7. 데이터 저장 원칙

### raw 자료

원본은 최대한 수정하지 않고 저장한다.

```text
data/brain/00_raw/YYYY-MM-DD/제목.md
```

### 정리 자료

AI 또는 사용자가 정리한 자료는 별도 저장한다.

```text
data/brain/10_wiki/주제.md
```

### 프로젝트 자료

사업계획서, 정책 개선, 마케팅 캠페인처럼 목적이 있는 자료는 프로젝트 단위로 둔다.

```text
data/brain/20_projects/프로젝트명/
```

### 민감정보

민감정보는 GitHub에 올리지 않는다.

향후 `.gitignore`와 안전 검사에 다음을 반영한다.

- API 키
- 인증 파일
- 주민번호/연락처 등 개인정보
- 계약서 원본
- 내부 전용 자료

## 9. 2주 실행 계획

이 계획은 일반적인 단독 개발 기준으로는 2주 단위로 잡는다.

- 실제 사용 가능한 MVP: 2~4일
- 정책/사업계획/마케팅 핵심 루프: 1~2주
- 로컬 UI를 포함한 제품형 버전: 3~5주

### 6~7일차

- `policy:structure` 구현
- 문제 구조표 Markdown 생성

### 8~9일차

## 10. 첫 번째 사용 시나리오

### 정책/시민 서비스 개선

1. 사용자가 민원 내용 또는 회의 메모를 복사한다.
2. `skill:menu`에서 `정책 문제 구조화`를 고른다.
3. `brain:capture`로 자료를 저장한다.
4. `ai:question`으로 AI에게 물어볼 질문을 만든다.
5. 사용자가 AI에 질문을 붙여넣는다.
6. 답변을 다시 저장한다.
7. `ai:review`로 답변을 검토한다.
8. `service:journey`로 시민 경험을 시각화한다.

### 사업계획서

1. 공고문을 붙여넣는다.
2. `plan:notice`로 요구사항을 뽑는다.
3. `plan:questions`로 AI 질문을 만든다.
4. 답변을 붙여넣는다.
5. `plan:draft`로 초안을 만든다.
6. `plan:check`로 제출 전 확인한다.

### 마케팅

1. 오늘 주제를 입력한다.
2. `marketing:ideas`로 아이디어를 만든다.
3. AI에게 캡션 변형을 요청한다.
4. 결과를 붙여넣는다.
5. `marketing:review`로 성과 기록 항목을 만든다.

## 11. 성공 기준

첫 번째 성공은 거대한 앱이 아니다.

첫 성공 기준:

- 사용자가 `skill:menu`에서 원하는 일을 고를 수 있다.
- 붙여넣은 자료가 로컬에 저장된다.
- AI에게 물어볼 좋은 질문이 자동으로 나온다.
- AI 답변을 다시 검토할 수 있다.
- 결과물이 Markdown으로 남는다.

중기 성공 기준:

- 사업계획서 초안 작성 시간이 절반 이하로 줄어든다.
- 정책/서비스 개선 회의 준비 시간이 줄어든다.
- 마케팅 콘텐츠 아이디어가 반복적으로 생산된다.
- 사용자가 매일 이 프로그램을 열 이유가 생긴다.

장기 성공 기준:
