# 레포 흡수 매핑

작성일: 2026-06-04

## 1. 기본 판단

여러 저장소를 물리적으로 한 덩어리로 합치지 않는다.

`my-workbench`를 개인 AI 업무 OS이자 지휘본부로 두고, 다른 저장소는 기능과 철학을 선별해서 흡수한다.

역할:

- `my-workbench`: 본부, CLI, 스킬, 데이터 구조, 문서 허브
- `connect-ai`: 로컬 세컨드브레인과 Git 동기화 철학
- `planning-copilot`: 공모/사업계획서 작성 워크플로우
- `markter`: 마케팅 브레인과 콘텐츠 생산 엔진
- `antigravity-awesome-skills`: 스킬 참고 라이브러리

## 2. 통합 원칙

1. 코드를 그대로 복사하기 전에 기능을 먼저 정의한다.
2. 사용자가 실제로 쓸 메뉴를 먼저 만든다.
3. 로컬 데이터와 민감정보는 GitHub에 올리지 않는다.
4. 자동 실행보다 미리보기와 확인을 우선한다.
5. 외부 AI/API는 선택 사항으로 둔다.
6. 모든 기능은 한글 메뉴와 객관식 선택을 기본값으로 둔다.

## 3. connect-ai 흡수 매핑

### 가져올 것

| 원본 아이디어 | my-workbench 위치 | 구현 방식 | 우선순위 |
| --- | --- | --- | --- |
| 로컬 세컨드브레인 | `data/brain/` | raw/wiki/projects/skills 구조 생성 | 높음 |
| raw 자료 저장 | `data/brain/00_raw/` | `brain:capture` 명령 | 높음 |
| raw → wiki 정리 | `data/brain/10_wiki/` | `ai:question`, `brain:wiki` 후보 | 중간 |
| GitHub 동기화 | `scripts/`, `apps/cli` | `brain:sync --dry-run`부터 시작 | 중간 |
| 로컬 우선 지식관리 | `docs/`, `data/brain/` | 문서와 데이터 구조로 재설계 | 높음 |

### 가져오지 않을 것

| 제외 대상 | 이유 |
| --- | --- |
| VS Code 확장 전체 구조 | 현재 목표는 로컬 업무본부와 CLI 우선 |
| 자동 force push 흐름 | 사용자 자료 손상 위험 |
| 과도한 자동 파일 수정 | 일반 사용자가 통제하기 어려움 |

### 첫 구현

```text
npm run dev:cli -- brain:capture
npm run dev:cli -- ai:question
npm run dev:cli -- brain:sync --dry-run
```

## 6. antigravity-awesome-skills 흡수 매핑

### 선별 기준

전부 가져오지 않는다. 먼저 10개만 검토한다.

선별 기준:

- 실제 사용자 업무와 연결되는가
- 한글 메뉴로 바꿀 수 있는가
- 무료/로컬 우선으로 쓸 수 있는가
- 민감정보 위험이 낮은가
- `my-workbench`의 정책/사업/마케팅/자료정리 축과 맞는가

### 1차 후보

| 후보 | 흡수 방향 | my-workbench 위치 |
| --- | --- | --- |
| `instagram-automation` | 인스타 운영 스킬 보강 | `skills/marketing-ops/`, `skills/instagram-ops/` |
| `launch-strategy` | 캠페인/사업 출시 전략 | `skills/marketing-ops/`, `packages/marketing/` |
| `kpi-dashboard-design` | 성과지표 설계 | `skills/policy-design/`, `skills/marketing-ops/` |
| `agent-memory-systems` | 로컬 지식 구조 참고 | `data/brain/`, `packages/core/` |
| `agent-orchestration-*` | 여러 스킬 연결 방식 참고 | `packages/core/skill-catalog.ts` |
| `llm-app-patterns` | AI 앱 설계 패턴 참고 | `docs/`, `packages/core/` |
| `llm-application-dev-prompt-optimize` | 질문 생성 품질 개선 | `packages/core/ai-question.ts` |
| `api-documentation-generator` | 내부 명령 문서화 | `docs/`, `apps/cli` |
| Google Drive 자동화 계열 | Drive 정리/백업 참고 | `skills/drive-ops/` 후보 |
| marketing/CRM/automation 계열 | 마케팅 운영 자동화 참고 | `skills/marketing-ops/` |

### 가져오지 않을 것

| 제외 대상 | 이유 |
| --- | --- |
| 보안 공격/침투 테스트 계열 | 현재 사용 목적과 다름 |
| 특정 클라우드 전문 스킬 | 비용/복잡도 증가 |
| 과도한 개발자 전용 스킬 | 일반 사용자 UX와 맞지 않음 |
| 라이선스가 불명확한 복사 코드 | 추후 리스크 |

## 9. 기능별 MVP

### MVP 1. 자료 붙여넣기

사용자가 자료를 붙여넣으면 로컬 Markdown으로 저장된다.

완료 기준:

- 날짜별 파일 생성
- 자료 종류 기록
- 제목/태그 기록
- 저장 경로 출력

### MVP 2. AI 질문 만들기

저장한 자료 또는 붙여넣은 자료로 AI 질문을 만든다.

완료 기준:

- 스킬별 질문 템플릿
- 복사 가능한 출력
- 민감정보 경고

### MVP 3. AI 답변 검토하기

AI 답변을 붙여넣으면 검토표를 만든다.

완료 기준:

- 사실성
- 논리
- 실행 가능성
- 시민 관점
- 리스크
- 수정 제안

### MVP 4. 사업계획서 도우미

공고문에서 요구사항과 질문을 뽑는다.

완료 기준:

- 요구사항 요약
- 제출 조건
- 필요한 자료
- AI 질문
- 체크리스트

### MVP 5. 마케팅 콘텐츠 만들기

주제에서 콘텐츠 아이디어와 캡션을 만든다.

완료 기준:

- 아이디어 10개
- 캡션 초안
- 해시태그
- 업로드 후 기록 항목

## 10. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 기능이 너무 많아짐 | `skill:menu` 중심으로 사용 흐름 제한 |
| 외부 AI 의존도 증가 | 질문 생성까지만 기본 제공, 외부 AI는 선택 |
| 민감정보 유출 | 전송 전 경고, 로컬 저장 우선 |
| 레포 통합 중 혼란 | 매핑표 기준으로 선별 흡수 |
| 일반 사용자가 어려워함 | 한글 메뉴, 객관식, 복사 버튼 중심 |
| 자동화가 위험해짐 | dry-run 기본값, 실행 전 확인 |
