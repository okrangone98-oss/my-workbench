# 로컬 AI 업무본부 통합 설계

작성일: 2026-06-04

## 1. 결론

`my-workbench`는 단순한 코드 저장소가 아니라, 사용자가 매일 쓰는 로컬 AI 업무본부로 키운다.

핵심 방향은 완전 자동화가 아니다. 일반 사용자가 이해하고 통제할 수 있도록 수동과 자동을 섞는다.

- 사용자는 자료를 복사해서 붙여넣는다.
- 모르는 부분은 AI에게 물어볼 질문으로 바꾼다.
- 반복되는 절차는 스킬과 CLI로 자동화한다.
- 비용이 드는 고급 판단은 필요한 순간에만 외부 AI/API를 사용한다.
- 원본 자료와 민감정보는 로컬 우선으로 둔다.

목표는 "AI가 다 알아서 하는 시스템"이 아니라, "내가 일하는 속도를 10배 빠르게 만드는 조수들의 작업대"다.

## 2. 사용자 기준 원칙

### 2-1. 로컬에서 먼저 잘 돌아가야 한다

사용자의 기본 작업 위치는 로컬 컴퓨터다.

- 자료는 먼저 로컬 폴더에 둔다.
- GitHub는 백업, 버전관리, 작업물 공유에 사용한다.
- Google Drive는 외부 공유와 원본 문서 보관에 사용한다.
- 민감정보, 계약서, 인증 파일, API 키는 GitHub에 올리지 않는다.

### 2-2. 일반인이 이해할 수 있어야 한다

명령어를 몰라도 쓸 수 있는 방향으로 설계한다.

1. 폴더를 고른다.
2. 자료를 붙여넣는다.
3. 버튼 또는 간단한 명령을 누른다.
4. 결과 초안을 본다.
5. AI에게 물어볼 질문을 복사한다.
6. 받은 답을 다시 붙여넣어 정리한다.

초기에는 CLI와 문서 템플릿으로 시작하고, 검증된 기능만 나중에 데스크톱 UI로 올린다.

### 2-3. 무료/오픈소스를 우선한다

우선순위는 다음과 같다.

1. 로컬 파일, Markdown, JSON, SQLite
2. 무료 오픈소스 라이브러리
3. 브라우저에서 동작하는 무료 도구
4. 사용자가 이미 쓰는 ChatGPT, Claude, Gemini 같은 AI
5. 꼭 필요할 때만 유료 API

## 3. 통합할 저장소 역할

### 3-1. my-workbench

역할: 본부, 기준 문서, CLI, 스킬, 자동화의 중심.

흡수 방식:

- 모든 통합 결과는 `my-workbench` 안에 문서화한다.
- 반복 업무는 `skills/`와 `packages/`로 옮긴다.
- 검증된 실행 흐름은 `apps/cli` 명령으로 만든다.

### 3-2. connect-ai

역할: 로컬 세컨드브레인, 자동 Git 동기화, raw 자료를 wiki로 정리하는 철학.

그대로 합치기보다 다음 아이디어를 가져온다.

- `00_Raw`: 사용자가 붙여넣은 원본 자료
- `10_Wiki`: 정리된 지식
- `20_Projects`: 실제 진행 중인 일
- `30_Skills`: 반복 업무 절차
- GitHub 자동 백업은 안전 모드부터 시작

우선 구현 후보:

- `data/brain/00_raw`
- `data/brain/10_wiki`
- `data/brain/20_projects`
- `data/brain/30_skills`
- `npm run dev:cli -- brain:capture`
- `npm run dev:cli -- brain:sync --dry-run`

### 3-3. planning-copilot

역할: 공고문, 사업계획서, 제안서 작성 워크플로우.

핵심 흐름:

1. 공고문 붙여넣기
2. 요구사항 추출
3. 필요한 질문 생성
4. 참고자료 모으기
5. AI에게 던질 프롬프트 생성
6. AI 답변 붙여넣기
7. 사업계획서 초안 조립
8. 제출 전 체크리스트 생성

우선 구현 후보:

- `skills/planning-copilot/`
- `packages/planning/`
- `apps/cli` 명령:
  - `plan:notice`
  - `plan:questions`
  - `plan:draft`
  - `plan:check`

### 3-4. markter

역할: 마케팅 브레인, 콘텐츠 생산, 브랜드 학습.

핵심 흐름:

1. 브랜드 정보 입력
2. 고객/페르소나 정리
3. 경쟁자/레퍼런스 수집
4. 콘텐츠 아이디어 생성
5. 인스타/블로그/쇼츠용 초안 생성
6. 성과 기록
7. 잘 된 패턴을 다음 콘텐츠에 반영

우선 구현 후보:

- `skills/marketing-ops/`
- `packages/marketing/`
- `data/marketing/brand-wiki`
- `data/marketing/content-history`
- `apps/cli` 명령:
  - `marketing:brief`
  - `marketing:ideas`
  - `marketing:caption`
  - `marketing:review`

### 3-5. antigravity-awesome-skills

역할: 스킬 참고 라이브러리.

전부 가져오지 않는다. 너무 많으면 오히려 사용하기 어려워진다.

1차 선별 후보:

- `instagram-automation`
- `launch-strategy`
- `kpi-dashboard-design`
- `agent-memory-systems`
- `agent-orchestration-*`
- `llm-app-patterns`
- `llm-application-dev-prompt-optimize`
- `api-documentation-generator`
- `google-drive` 관련 자동화
- `marketing` / `crm` / `automation` 계열

흡수 기준:

- 실제 사용자 업무에 바로 연결되는가
- 무료 또는 로컬 우선으로 쓸 수 있는가
- 스킬 설명이 일반 사용자가 이해할 수 있는가
- 민감정보를 외부로 보내지 않아도 되는가

## 4. 핵심 역량 축

이 업무본부는 단순히 문서를 빨리 만드는 도구가 아니다. 사용자가 AI를 정책 설계, 의사결정, 시민 서비스 개선에 활용할 수 있도록 사고 과정을 도와야 한다.

### 4-1. 좋은 질문을 던지는 능력

AI 활용의 품질은 질문의 품질에서 시작된다.

업무본부는 다음을 도와야 한다.

- 막연한 고민을 구체적 질문으로 바꾸기
- 상황, 목표, 제약, 이해관계자를 분리하기
- AI에게 맡길 질문과 사람이 판단할 질문을 구분하기
- 한 번의 큰 질문보다 단계별 질문 묶음을 만들기

예시:

- "이 사업을 어떻게 하면 좋을까?"보다 "이 사업의 정책 목표, 대상자, 실행 제약, 성과지표를 분리해서 검토해줘"
- "홍보 문구 써줘"보다 "대상 시민의 불안, 기대, 행동 장벽을 고려해서 3가지 톤으로 안내문을 만들어줘"

### 4-2. 문제의 구조를 파악하는 능력

정책과 운영 문제는 대부분 단일 원인이 아니다.

업무본부는 문제를 다음 구조로 나누도록 돕는다.

- 현상: 지금 보이는 문제
- 원인: 반복해서 문제를 만드는 구조
- 이해관계자: 영향을 받는 사람과 실행하는 사람
- 제약: 예산, 인력, 법령, 시간, 시스템
- 선택지: 가능한 대응안
- 리스크: 실패하거나 오해받을 지점
- 지표: 개선 여부를 확인할 수 있는 기준

### 4-3. 사업의 논리를 설계하는 능력

사업계획서와 정책 제안은 글쓰기 이전에 논리 설계가 필요하다.

기본 구조:

1. 왜 필요한가
2. 누구의 문제인가
3. 어떤 변화가 목표인가
4. 어떤 활동을 할 것인가
5. 왜 이 방식이 효과적인가
6. 무엇으로 성과를 볼 것인가
7. 어떤 위험이 있고 어떻게 줄일 것인가

`planning-copilot`은 이 축을 중심으로 흡수한다.

### 4-4. 사용자 경험과 운영 과정을 시각화하는 능력

정책과 시민 서비스는 실제 이용 흐름으로 검증해야 한다.

업무본부는 다음 산출물을 만들 수 있어야 한다.

- 시민 여정 지도
- 업무 처리 흐름도
- 접수-검토-처리-피드백 단계표
- 담당자별 역할표
- 병목 지점 목록
- 개선 전/후 비교표

초기에는 Mermaid 다이어그램과 Markdown 표로 시작한다.

### 4-5. AI 결과물을 판단하고 수정하는 능력

AI가 만든 결과물은 정답이 아니라 초안이다.

검토 기준:

- 사실이 맞는가
- 정책 목적과 맞는가
- 시민 입장에서 이해하기 쉬운가
- 실행 담당자가 실제로 할 수 있는가
- 민감하거나 차별적인 표현은 없는가
- 빠진 이해관계자는 없는가
- 법적/행정적 검토가 필요한 부분은 표시됐는가

이 기준은 향후 `skills/ai-reviewer` 또는 `skills/policy-reviewer`로 분리한다.

### 4-6. 정책 설계, 의사결정, 시민 서비스 개선에 AI 쓰기

AI 활용 분야를 다음 5개로 나눈다.

1. 정책 설계
   - 문제 정의
   - 대상자 분석
   - 대안 비교
   - 성과지표 설계

2. 의사결정 보조
   - 장단점 표
   - 리스크 목록
   - 이해관계자 영향 분석
   - 결정 전 질문 목록

3. 시민 서비스 개선
   - 민원/문의 유형 정리
   - 안내문 개선
   - 신청 절차 단순화
   - 시민 여정 지도 작성

4. 사업계획 및 보고
   - 공고문 분석
   - 제안 논리 구성
   - 실행계획 작성
   - 성과보고 초안 작성

5. 운영 자동화
   - 반복 문서 템플릿
   - 체크리스트
   - 회의 메모 정리
   - 후속 작업 추출

## 5. 수동+자동 하이브리드 작업 방식

### 5-1. 수동으로 남겨야 하는 것

다음은 사용자가 직접 확인해야 한다.

- 민감한 자료 업로드 여부
- 최종 제출 문서 승인
- 외부 AI에게 보낼 내용
- GitHub push 전 변경사항 확인
- 유료 API 사용 여부

### 5-2. 자동화할 것

다음은 자동화해도 좋다.

- 폴더 구조 생성
- 원본 자료 날짜별 저장
- Markdown 템플릿 생성
- AI 질문 생성
- 초안 조립
- 체크리스트 생성
- 중복 파일 후보 탐지
- Git 변경사항 요약
- dry-run 기반 백업 계획

### 5-3. AI에게 맡길 것

다음은 AI가 잘한다.

- 복잡한 문서 요약
- 공고문 요구사항 해석
- 좋은 질문 만들기
- 글 초안 작성
- 마케팅 문구 변형
- 놓친 리스크 찾기
- 자료 간 연결점 찾기

단, AI 답변은 항상 "초안"으로 취급한다.

## 6. 사용자 경험 목표

최종적으로 사용자는 다음처럼 쓰게 만든다.

### 예: 사업계획서

1. 공고문을 `data/brain/00_raw`에 저장한다.
2. `plan:notice`로 요구사항을 뽑는다.
3. `plan:questions`로 AI에게 물어볼 질문을 만든다.
4. ChatGPT/Claude/Gemini에 질문을 붙여넣는다.
5. 답변을 다시 저장한다.
6. `plan:draft`로 초안을 만든다.
7. `plan:check`로 제출 전 점검표를 만든다.

### 예: 정책/시민 서비스 개선

1. 민원, 회의 메모, 현장 의견을 붙여넣는다.
2. `policy:structure`로 문제 구조를 나눈다.
3. `policy:questions`로 추가 확인 질문을 만든다.
4. AI에게 대안과 리스크를 물어본다.
5. 답변을 붙여넣고 `policy:decision`으로 비교표를 만든다.
6. `service:journey`로 시민 여정과 운영 흐름을 시각화한다.
7. `policy:review`로 빠진 이해관계자와 검토 필요 사항을 확인한다.

### 예: 인스타 콘텐츠

1. 오늘 주제를 입력한다.
2. `marketing:brief`로 브랜드/고객 맥락을 모은다.
3. `marketing:ideas`로 10개 아이디어를 만든다.
4. 마음에 드는 것을 고른다.
5. `marketing:caption`으로 캡션과 해시태그를 만든다.
6. 업로드 후 성과를 `marketing:review`로 기록한다.

### 예: 자료 정리

1. 폴더를 지정한다.
2. `scan:folders`로 현황을 본다.
3. `apply:scan`으로 이동 계획만 만든다.
4. 사용자가 확인한다.
5. `--apply`는 확신이 있을 때만 실행한다.

## 7. 1차 구현 로드맵

### Phase 1. 문서와 구조 정리

- 이 통합 설계를 기준 문서에 연결한다.
- 레포별 흡수 매핑표를 만든다.
- `data/brain` 기본 폴더 구조를 만든다.
- 스킬 표준 템플릿을 정한다.
- 새 스킬은 한글 메뉴, 객관식 선택, 복사/붙여넣기 흐름을 기본값으로 둔다.

### Phase 2. 복사/붙여넣기 기반 워크플로우

- `brain:capture`: 원본 자료 저장
- `ai:question`: AI에게 물어볼 질문 생성
- `ai:answer`: AI 답변 저장
- `draft:assemble`: 초안 조립

### Phase 3. 사업계획서, 정책 설계, 마케팅 우선 적용

- `planning-copilot` 흐름을 `skills/planning-copilot`으로 흡수
- `markter` 흐름을 `skills/marketing-ops`로 흡수
- 기존 `instagram-ops`와 연결
- `skills/policy-design` 초안을 만든다.
- `skills/service-improvement` 초안을 만든다.
- `skills/ai-output-review` 초안을 만든다.

### Phase 4. 로컬 UI

CLI로 검증된 기능만 데스크톱 UI로 올린다.

초기 화면:

- 오늘 작업
- 자료 붙여넣기
- AI 질문 만들기
- 초안 만들기
- GitHub 백업 상태

## 8. 성공 기준

1. 사용자가 명령어를 몰라도 문서를 보고 따라할 수 있다.
2. 공고문에서 사업계획서 초안까지 걸리는 시간이 절반 이하로 줄어든다.
3. 인스타/블로그 콘텐츠 초안 생성이 반복 가능해진다.
4. 로컬 자료가 날짜와 프로젝트 기준으로 쌓인다.
5. GitHub에는 민감정보 없이 결과물과 기준 문서만 올라간다.
6. 유료 API 없이도 기본 흐름이 동작한다.
7. 유료 AI/API는 "선택적 가속 장치"로만 쓰인다.
8. 정책/사업/서비스 개선 업무에서 문제 구조, 대안, 리스크, 시민 경험을 빠르게 정리할 수 있다.
9. AI 결과물을 그대로 쓰지 않고 검토 기준에 따라 수정할 수 있다.
