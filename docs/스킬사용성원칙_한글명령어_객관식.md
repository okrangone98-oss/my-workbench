# 스킬 사용성 원칙: 한글 명령어와 객관식 흐름

작성일: 2026-06-04

## 1. 목적

`my-workbench`의 스킬은 개발자가 아니라 실제 사용자가 편하게 쓰는 업무 도구여야 한다.

따라서 새 스킬은 다음을 기본 원칙으로 만든다.

- 한글 이름과 한글 명령어를 우선한다.
- 사용자가 무엇을 해야 할지 바로 알 수 있어야 한다.
- 가능한 경우 객관식으로 고르게 한다.
- 복사/붙여넣기만으로 시작할 수 있어야 한다.
- 자동 실행 전에는 항상 미리보기와 확인 단계를 둔다.
- AI에게 물어볼 질문을 직접 만들어준다.

## 2. 스킬 이름 원칙

스킬 이름은 기술명보다 사용자가 원하는 결과를 드러낸다.

좋은 예:

- `사업계획서 도우미`
- `정책 문제 구조화`
- `시민 서비스 개선`
- `AI 답변 검토`
- `인스타 콘텐츠 만들기`
- `자료 정리 판단`

피할 예:

- `planning-copilot-core`
- `policy-analyzer-v2`
- `automation-pipeline`
- `prompt-processor`

내부 폴더명은 영어를 써도 되지만, 사용자에게 보이는 이름은 한글로 둔다.

## 3. 명령어 원칙

CLI 명령은 영어를 유지할 수 있지만, 반드시 한글 별칭 또는 한글 안내를 붙인다.

예:

```text
사업계획서 시작하기
  내부 명령: plan:start

공고문 분석하기
  내부 명령: plan:notice

AI에게 물어볼 질문 만들기
  내부 명령: ai:question

초안 만들기
  내부 명령: draft:assemble

제출 전 점검하기
  내부 명령: plan:check
```

사용자 안내에서는 내부 명령보다 한글 동작 이름을 먼저 보여준다.

## 4. 객관식 선택 원칙

사용자가 막히는 지점은 입력칸보다 선택지를 먼저 제공한다.

기본 선택지 형식:

```text
무엇을 하시겠어요?

1. 새 자료 붙여넣기
2. 기존 자료 불러오기
3. AI에게 물어볼 질문 만들기
4. 초안 만들기
5. 제출/공유 전 점검하기
```

선택지는 3~7개 안에서 유지한다. 너무 많으면 "기타" 또는 "고급 설정"으로 뺀다.

## 5. 스킬 기본 흐름

모든 스킬은 가능하면 다음 흐름을 따른다.

1. 목적 고르기
2. 자료 붙여넣기 또는 파일 선택
3. 자동 분석 결과 미리보기
4. AI에게 물어볼 질문 생성
5. 사용자가 외부 AI에 질문
6. AI 답변 붙여넣기
7. 초안/표/체크리스트 생성
8. 최종 확인

이 흐름은 무료 도구와 유료 AI를 자연스럽게 섞기 위한 기본 구조다.

## 6. 자동화 안전 원칙

자동화는 사용자를 대신해 판단하지 않는다. 판단을 쉽게 하도록 돕는다.

필수 안전장치:

- 삭제, 이동, push, 외부 업로드는 기본값을 `미리보기`로 둔다.
- 실제 실행은 `실행하기`를 한 번 더 선택해야 한다.
- 민감정보 가능성이 있으면 경고한다.
- AI에게 보낼 내용은 전송 전에 보여준다.
- 유료 API 사용 전에는 비용 가능성을 알려준다.

## 7. 출력물 원칙

출력물은 사용자가 바로 복사해서 쓸 수 있어야 한다.

기본 출력 형식:

- 요약
- 다음 행동
- AI에게 물어볼 질문
- 표 또는 체크리스트
- 복사 가능한 초안
- 확인해야 할 위험

예:

```text
다음으로 할 일

1. 아래 질문을 ChatGPT/Claude/Gemini에 붙여넣으세요.
2. 받은 답변을 다시 이 스킬에 붙여넣으세요.
3. 스킬이 초안과 점검표를 만들어줍니다.
```

## 8. 정책/사업/시민서비스 스킬의 필수 질문

정책 설계, 의사결정, 시민 서비스 개선 스킬은 다음 질문을 반드시 포함한다.

1. 이 문제는 누구의 문제인가?
2. 지금 보이는 현상과 실제 원인은 무엇인가?
3. 영향을 받는 시민/이용자는 누구인가?
4. 실행하는 담당자는 누구인가?
5. 예산, 인력, 법령, 시간 제약은 무엇인가?
6. 가능한 대안은 무엇인가?
7. 각 대안의 장단점과 리스크는 무엇인가?
8. 성공 여부를 어떤 지표로 볼 것인가?
9. 시민 입장에서 가장 불편한 지점은 어디인가?
10. AI 답변 중 사람이 반드시 검토해야 할 부분은 무엇인가?

## 9. 스킬 작성 체크리스트

새 스킬을 만들 때 다음을 확인한다.

- [ ] 사용자에게 보이는 이름이 한글인가?
- [ ] 첫 화면에서 무엇을 할 수 있는지 바로 보이는가?
- [ ] 객관식 선택지가 있는가?
- [ ] 복사/붙여넣기만으로 시작할 수 있는가?
- [ ] AI에게 물어볼 질문을 만들어주는가?
- [ ] 결과물이 표, 체크리스트, 초안 중 하나로 나오는가?
- [ ] 실제 실행 전 미리보기가 있는가?
- [ ] 민감정보/비용/API 사용 경고가 있는가?
- [ ] 사용자가 다음에 무엇을 해야 하는지 분명한가?

## 10. 앞으로의 기본값

앞으로 `my-workbench`에서 새 스킬을 만들 때는 이 문서를 기본 UX 기준으로 삼는다.

기술 구현보다 먼저 다음 3가지를 정한다.

1. 사용자가 고를 한글 메뉴
2. 사용자가 붙여넣을 자료
3. 사용자가 복사해 외부 AI에게 던질 질문
