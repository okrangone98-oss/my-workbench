# 민감정보 분리 전략

## 1. 목적

프로젝트 통합 과정에서 인증/토큰/키 파일이 Git에 포함되는 위험을 줄이고, 로컬 개발은 유지한다.

## 2. 현재 확인된 민감 파일 유형

- `.env.local`, `.env*`
- `credentials.json`, `token.json`, `paypal_token.json`
- 서비스 계정 JSON, 인증서/키 파일

## 3. 저장 원칙

1. 비밀값은 코드 저장소 밖의 로컬 전용 경로에 둔다.
2. 저장소에는 예시 파일(`*.example`)만 둔다.
3. 코드에서는 절대 경로 하드코딩 대신 환경변수만 사용한다.
4. 로그/리포트에는 비밀값 원문을 쓰지 않는다.

## 4. 권장 로컬 경로

- `G:\private\secrets\`
- `G:\private\tokens\`

환경변수 예시:
- `GOOGLE_CREDENTIALS_PATH=G:\private\secrets\google_credentials.json`
- `GOOGLE_TOKEN_PATH=G:\private\tokens\google_token.json`

## 5. 커밋 전 체크

1. `git status`에 `.env`, `token`, `credentials`류 파일이 보이면 중단
2. 변경 파일에서 API 키 문자열 포함 여부 검색
3. `.example` 파일만 반영됐는지 확인

## 6. 운영 규칙

- 회사 업무용 자격증명은 개인용과 물리적으로 분리
- 만료 가능한 토큰은 주기적으로 교체
- 의심 파일이 발견되면 즉시 회수/재발급
