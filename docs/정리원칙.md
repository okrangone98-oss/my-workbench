# 정리원칙

## 1. 기본 원칙

1. 삭제보다 분류를 우선한다.
2. 3개월 미만 자료는 모두 점검 대상이다.
3. 장기 보존 자료는 로컬 원본을 기준으로 관리한다.
4. 동일 목적 자료는 하나의 프로젝트 흐름으로 통합한다.
5. 민감정보는 GitHub 반영 대상에서 즉시 제외한다.

## 2. 최근 자료(3개월 미만) 판정 질문

- 현재 프로젝트 목적과 직접 관련이 있는가?
- 동일/유사 자료의 최신본이 이미 존재하는가?
- 상위 구조로 통합 가능한가?
- 장기 보존 가치가 있는가?
- 삭제 후보로 두어도 업무 리스크가 없는가?

## 3. 처리 액션 정의

- 유지: 현재 구조에서 그대로 사용
- 통합: 동일 목적 자산과 병합
- 이동: 저장 위치 기준에 맞는 위치로 재배치
- 보관: 장기 보존 위치로 이동
- 삭제 후보: 즉시 삭제하지 않고 후보 목록에 등록

## 4. 통합 실행 규칙

1. 문서는 최신본 1개를 기준본으로 지정한다.
2. 중복 초안은 기준본 링크/참조만 남긴다.
3. 코드/문서/프롬프트/자동화는 기능 단위로 같은 경로 아래 배치한다.
4. 통합 후 기존 위치에는 1회성 정리 메모를 남긴다.

## 5. 삭제 후보 보고 원칙

삭제 후보는 반드시 목록으로 먼저 관리한다. 후보 목록 필수 항목:

- 파일명
- 위치
- 생성일
- 수정일
- 추정 용도
- 삭제 후보 사유
- 대체본 존재 여부

## 6. 삭제 전 체크리스트

- 백업 여부 확인
- 대체본 위치 확인
- 최근 참조 여부 확인
- 프로젝트 의존성 확인
- 민감정보 포함 여부 확인

체크리스트를 충족하기 전에는 삭제를 실행하지 않는다.

## 7. 커밋 단위 원칙

- 기준 문서 변경, 구조 변경, 파일 이동을 분리 커밋한다.
- 커밋 메시지는 영향 범위 + 작업 목적을 포함한다.
- 민감정보 점검 후에만 원격 반영한다.
