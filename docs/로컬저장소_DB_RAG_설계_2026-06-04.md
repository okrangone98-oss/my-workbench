# 로컬 저장소, DB, RAG 파일 설계

## 기본 원칙

1. 민감 자료는 먼저 로컬에 저장한다.
2. 배포된 웹앱은 사용하기 쉬운 화면으로 두고, 장기 보관 자료는 G드라이브 작업 폴더에 둔다.
3. 여러 기기 동기화, 로그인, 팀 공유가 필요해질 때 Supabase를 붙인다.

## 추천 저장 위치

프로젝트 기준 경로:

```text
G:\03_개발작업공간\my-work-bench
```

데이터 저장 위치:

```text
data/
  brain/
    00_raw/        복사해 붙인 원본 자료
    10_wiki/       사람이 읽기 좋게 정리한 지식
    20_projects/   사업계획서, 정책, 마케팅 등 프로젝트별 자료
    30_skills/     반복 업무 스킬 기록
  rag/
    documents/     검색 대상으로 삼을 원본 문서
    index/         나중에 만들 문서 검색 색인
  db/
    local.sqlite   향후 로컬 앱에서 사용할 작은 DB
  exports/
    reports/       결과 보고서
    prompts/       AI에게 복사할 질문 모음
```

## 1차 개발 방식

- React 웹앱: 사람이 쉽게 입력하고 결과를 복사하는 화면
- CLI: 로컬 파일 저장, 정리, GitHub 백업 같은 컴퓨터 작업
- 로컬 데이터: `data/` 아래 저장
- Netlify 배포: 화면 배포용

## 나중에 추가할 것

- 로컬 SQLite DB
- 문서 RAG 색인 생성
- 내 컴퓨터 폴더에서 문서 끌어오기
- Supabase 동기화 옵션
- Google Drive 백업 옵션

## 사용자가 기억할 한 문장

중요한 자료는 먼저 내 컴퓨터 G드라이브 작업 폴더에 저장하고, 배포된 웹앱은 정리와 질문 생성을 돕는 화면으로 사용한다.
