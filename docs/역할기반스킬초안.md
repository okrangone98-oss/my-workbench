# 역할 기반 스킬 초안

## 1. 목적

개인/회사 업무를 돕는 에이전트와 스킬을 페르소나가 아니라 역할 중심으로 재정의한다.

## 2. 왜 재정의가 필요한가

- 페르소나형 스킬은 말투와 캐릭터는 다르지만 실제 작업 로직이 중복되기 쉽다.
- 장기적으로는 역할, 입력, 출력, 절차가 분명한 스킬이 유지보수에 유리하다.

## 3. 권장 스킬 세트

### `asset-classifier`

- 용도:
  - 로컬/Drive/GitHub 자산을 `KEEP/MERGE/MOVE/ARCHIVE/DELETE_CANDIDATE`로 판정
- 입력:
  - 폴더 목록, 수정일, 자산 메타
- 출력:
  - 인벤토리 표, 점검표, 삭제 후보 보고서

### `project-consolidator`

- 용도:
  - 중복 프로젝트와 리소스 폴더를 찾아 기준본/보조본 구조로 정리
- 입력:
  - 프로젝트 목록, 실행 진입점, README, package metadata
- 출력:
  - 통합 대상 목록, 기준본 지정, 이동 계획

### `company-ops-assistant`

- 용도:
  - 회사 프로젝트 문서, 보고서, 제안서, 운영 기록 지원
- 입력:
  - 문서 초안, 일정, 업무 맥락
- 출력:
  - 정리된 보고서, 체크리스트, 후속 액션

### `personal-ops-assistant`

- 용도:
  - 개인 업무, 아이디어, 자료, 개발 작업 정리
- 입력:
  - 메모, 파일 경로, 프로젝트 상태
- 출력:
  - 우선순위 목록, 정리 계획, 실행 문서

### `document-standardizer`

- 용도:
  - README, PRD, 운영 문서를 저장소 기준 형식으로 통일
- 입력:
  - 기존 문서
- 출력:
  - 정리된 문서와 링크 구조

## 4. 앱과의 관계

- 스킬은 Codex 작업 절차를 표준화한다.
- 앱은 사용자가 직접 실행하는 UI/CLI 도구다.
- 동일 규칙을 공유하되, 구현 위치는 분리한다.

## 5. 다음 단계

1. 위 5개 중 우선순위 2개를 먼저 스킬로 만든다.
2. 앱 쪽에서는 동일 역할 이름으로 모듈을 맞춘다.
3. 페르소나형 기존 스킬은 참고 자료로만 남기고 운영 기준에서는 제외한다.
