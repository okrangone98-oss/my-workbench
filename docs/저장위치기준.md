# 저장위치기준

## 1. 목적

로컬, Google Drive, GitHub의 역할을 분리해 자산 위치를 일관되게 유지한다.

## 2. 위치별 기본 역할

### 로컬 컴퓨터

- 실제 실행/작업 환경
- 장기 보존 원본 저장소
- 최근 생성 자료 1차 집결지
- 정리 작업의 기본 기준 경로: `G:\`

대표 대상:
- 사진자료
- 오래 보관한 중요 파일
- 민감 원본
- 최종 산출물 원본

### Google Drive

- 문서 아카이브 및 공유 자료 저장소
- 대용량 파일 보관
- 회사/콘텐츠 자료 분리 보관

대표 대상:
- 회사 문서
- 콘텐츠 자료
- 대용량 참고 자료
- 외부 공유 문서

### GitHub

- 프로젝트 운영 본부
- 문서/코드/프롬프트/자동화/변경 이력 관리

대표 대상:
- PRD/운영 문서
- 코드/스크립트
- 재사용 프롬프트
- 템플릿/워크플로

## 3. 위치 결정 규칙

1. 실행 가능한 자산인가?
- 예: GitHub(코드) + 로컬(실행본)

2. 장기 보존 원본인가?
- 예: 로컬 우선, 필요 시 Drive 백업

3. 외부 공유가 필요한가?
- 예: Drive(최소 권한)

4. 버전 추적이 필요한가?
- 예: GitHub 반영

5. 민감정보가 포함되어 있는가?
- 예: GitHub 금지, 로컬 분리 보관

## 4. GitHub 반영 금지 항목

- 개인정보/금융정보
- API 키/토큰/인증서
- 계정 비밀번호
- 회사 민감 원본자료
- 비공개 설정 파일(.env, 인증 키 파일)

## 5. 권장 경로 운영(개념)

로컬 권장 폴더:
- `G:\장기보관자료\`
- `G:\최근3개월검토\`
- `G:\진행중프로젝트\`

Drive 권장 폴더:
- 회사프로젝트/
- 개인프로젝트/
- 콘텐츠자료/
- 보관자료/

GitHub 권장 폴더:
- docs/
- prompts/
- templates/
- apps/
- automation/
- workflows/

## 6. 이동/동기화 원칙

- 원본은 1개 위치를 기준으로 지정한다.
- 동기화본은 파일명 또는 메타데이터로 원본 위치를 추적 가능하게 한다.
- 이동 시 이유와 날짜를 문서/커밋에 남긴다.
