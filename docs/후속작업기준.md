# 후속작업기준

## 1. 목적

PRD 기준으로 초기 구조를 안정화한 뒤, 실제 운영 데이터에 맞춰 저장소를 점진 확장하기 위한 실행 게이트를 정의한다.

## 2. 기본 원칙

1. `docs` 중심으로 먼저 운영한다.
2. 폴더는 필요가 확인될 때만 추가한다.
3. 폴더 추가 전 "대상 파일 5개 이상" 또는 "반복 작업 3회 이상" 증거를 남긴다.
4. 민감정보가 포함될 수 있는 자산은 GitHub가 아닌 로컬/Drive에 둔다.

## 3. 단계별 작업 기준

### Stage A: 기준 문서 고정

완료 조건:
- PRD, 정리원칙, 자산분류기준, 저장위치기준 문서가 서로 충돌 없이 정합
- 운영절차 문서에 실제 산출물 정의

### Stage B: 자산 인벤토리

완료 조건:
- 로컬/Drive/GitHub 대상 자산 목록 작성
- 최근 3개월 자료 태깅 완료
- 장기 보존 후보 태깅 완료

### Stage C: 1차 판정 및 실행

완료 조건:
- 자산별 상태값(`KEEP`, `MERGE`, `MOVE`, `ARCHIVE`, `DELETE_CANDIDATE`) 부여
- 통합/이동 실행 로그 기록
- 삭제 후보 목록 작성(즉시 삭제 금지)

### Stage D: 구조 확장

완료 조건:
- 신규 폴더별 목적/포함/제외 자산이 문서화됨
- 2주 이상 실제 사용 사례가 확인됨

## 4. 폴더 확장 게이트

### `prompts/` 추가 조건

- 재사용 가능한 프롬프트가 5개 이상 누적
- 같은 입력/출력 형식이 반복됨

### `templates/` 추가 조건

- 반복 문서 양식(PRD 보강안, 점검표, 보고서)이 3회 이상 재사용됨

### `workflows/` 추가 조건

- 업무 절차를 흐름도로 분리할 필요가 있을 정도로 단계가 증가함

### `automation/` 추가 조건

- 정기 점검, 분류, 리포트 생성 등 자동화 스크립트를 운영에 투입함

### `apps/` 추가 조건

- 코드 실행물(CLI/스크립트/서비스)이 2개 이상 운영됨

### `references/`, `archive/` 추가 조건

- 참고자료와 기준문서가 혼재되어 탐색 비용이 증가함

## 5. 우선순위 백로그(권장)

1. 자산 인벤토리 템플릿 작성
2. 최근 3개월 자료 점검표 작성
3. 삭제 후보 보고서 템플릿 작성
4. 주간 점검 로그 양식 작성
5. Stage D 진입 여부 월간 평가

## 6. 운영 주기

- 주간: 최근 3개월 자료 점검
- 월간: 삭제 후보 검토 및 구조 확장 필요성 판단
- 분기: PRD/기준 문서 재검토 및 폴더 구조 재설계 여부 결정
