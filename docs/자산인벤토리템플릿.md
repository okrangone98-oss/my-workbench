# 자산인벤토리 템플릿

## 1. 목적

로컬/Google Drive/GitHub에 분산된 자산을 한 표에서 관리하고, 분류 및 후속 액션의 기준 데이터를 만든다.

## 2. 작성 원칙

1. 자산 1개(또는 폴더 1개)당 1행으로 기록한다.
2. 최근 3개월 자료 여부와 장기 보존 여부를 반드시 표기한다.
3. 분류 상태는 `KEEP`, `MERGE`, `MOVE`, `ARCHIVE`, `DELETE_CANDIDATE` 중 하나를 사용한다.
4. 민감정보 가능성이 있으면 `민감정보` 칸에 표시하고 GitHub 업로드 금지로 처리한다.

## 3. 인벤토리 표

| ID | 자산명 | 자산유형 | 현재위치(Local/Drive/GitHub) | 원본경로 | 생성일 | 수정일 | 최근3개월 | 장기보존후보 | 분류상태 | 민감정보 | 대체본/백업 | 다음액션 | 검토일 | 검토자 | 메모 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| A-001 | 예시_운영문서.md | 문서 | GitHub | `/docs/example.md` | 2026-03-01 | 2026-03-05 | Y | N | KEEP | N | Y(Drive) | 유지 | 2026-03-07 | odh | 샘플 |

## 4. 작성 가이드

- `자산유형` 예시: 문서, 코드, 프롬프트, 이미지, 영상, 계약/증빙, 자동화
- `최근3개월` 기준: 작성 시점 기준 90일 이내면 `Y`
- `장기보존후보` 예시: 사진 원본, 중요 계약, 핵심 결과물 원본
- `다음액션` 예시: 유지, 통합, 이동, 보관, 삭제후보등록

## 5. 저장 규칙

- 주간 점검 파일은 날짜를 붙여 보관한다. 예: `자산인벤토리_2026-03-07.md`
- 원본 템플릿은 이 문서를 유지하고, 실행본은 별도 파일로 복제해 사용한다.
