# 프로그램 통합 제안

## 1. 결론

로컬 Windows에서 쓰는 작은 프로그램을 `npm` 기반 패키지 구조로 만들고, 이후 웹앱으로 확장하는 방식이 적합하다.

핵심은 처음부터 "하나의 앱"이 아니라 "공용 코어 + 여러 실행기" 구조로 시작하는 것이다.

## 2. 권장 구조

```text
workspace/
  package.json
  apps/
    desktop/
    web/
    cli/
  packages/
    core/
    agents/
    skills/
    data-access/
    ui/
```

## 3. 역할 분리

- `packages/core`
  - 업무 규칙, 분류 로직, 자산 판정, 공통 유틸
- `packages/agents`
  - 회사업무/개인업무용 에이전트 정의
  - 에이전트별 역할, 입력, 출력, 실행 흐름
- `packages/skills`
  - 재사용 스킬 문서와 보조 스크립트
  - Codex 스킬과 연결 가능한 구조
- `packages/data-access`
  - 로컬 파일 시스템, CSV, JSON, SQLite 접근
- `apps/cli`
  - 가장 먼저 만드는 실행기
  - 빠르고 토큰/개발비용이 가장 낮음
- `apps/desktop`
  - 로컬 전용 GUI
  - 나중에 Electron 또는 Tauri 선택
- `apps/web`
  - 웹 UI
  - 이미 검증된 `core`를 재사용

## 4. 왜 이 구조가 맞는가

1. 지금 필요한 것은 "내가 매일 쓰는 도구"다.
2. 웹앱을 먼저 만들면 배포, 인증, 보안, 상태관리 비용이 커진다.
3. CLI 또는 로컬 데스크톱으로 먼저 검증하면 실제 업무 흐름을 빠르게 고정할 수 있다.
4. 공통 로직을 `packages/core`에 두면 웹앱 전환 시 다시 만들 필요가 없다.

## 5. 우선 구현 순서

1. `apps/cli`
2. `packages/core`
3. `packages/agents`
4. `packages/skills`
5. 필요 시 `apps/desktop`
6. 충분히 검증된 후 `apps/web`

## 6. 중복 프로그램 통폐합 원칙

- 화면이 다르더라도 핵심 기능이 같으면 `core`로 통합한다.
- 프로젝트별로 따로 만든 파일 탐색, 분류, 로그 기능은 하나의 공용 모듈로 묶는다.
- 에이전트 문서와 스킬 문서는 실행 앱과 분리하고 `packages/agents`, `packages/skills`에서 중앙 관리한다.
- UI는 달라도 판정 규칙은 하나만 유지한다.

## 7. 추천 기술 스택

- 패키지 매니저: `npm workspaces`
- 언어: `TypeScript`
- 로컬 데이터: `SQLite` 또는 `JSON`
- CLI: `tsx` 또는 `node`
- 데스크톱:
  - 빠른 시작: `Electron`
  - 더 가벼운 배포: `Tauri`
- 웹:
  - `Next.js` 또는 `Vite + React`

## 8. 회사/개인 업무용 에이전트 예시

- 자산분류 에이전트
  - 로컬 폴더를 스캔하고 `KEEP/MERGE/MOVE/ARCHIVE/DELETE_CANDIDATE` 판정 초안을 생성
- 프로젝트정리 에이전트
  - 중복 프로젝트를 찾아 기준본과 보조본을 정리
- 문서정리 에이전트
  - README, PRD, 운영문서를 표준 형식으로 맞춤
- 회사업무 보조 에이전트
  - 제안서/보고서/회의록/자료요청 업무 흐름 보조
- 개인업무 보조 에이전트
  - 아이디어, 학습자료, 개발자산, 콘텐츠 초안 정리

## 9. 지금 사용자가 알아야 할 점

- 스킬 문서와 앱 코드는 같은 것이 아니다.
- 스킬은 "Codex가 작업하는 법"을 정의하고, 앱은 "사용자가 직접 쓰는 도구"다.
- 둘을 섞어두면 중복이 심해지므로 초기에 분리해야 한다.
- 민감정보가 들어가는 회사업무 데이터는 웹앱보다 로컬 앱이 먼저다.
