# PRD: my-workbench

## 1. 프로젝트 개요

my-workbench는 개인+회사 디지털 업무 자산을 통합 관리하는 작업본부 저장소다. 코드 저장소를 넘어 문서, 프롬프트, 자동화, 운영 기준을 함께 관리한다.

## 2. 목표

1. 디지털 업무 자산과 흐름의 체계적 관리
2. 로컬, Google Drive, GitHub 역할 분리
3. 장기 보존 자료와 최근 3개월 자료의 구분 관리
4. 문서, 프롬프트, 코드, 자동화 자산의 GitHub 중심 정리

## 3. 핵심 원칙

1. 로컬 사진자료/오래 보관 파일/중요 원본은 장기 보존 대상
2. 로컬 생성 3개월 미만 자료는 전수 점검 대상
3. 최근 자료는 `유지/통합/이동/보관/삭제후보`로 분류
4. 삭제는 즉시 하지 않고 중복/백업/대체본/통합 가능성 선검토
5. Google Drive는 회사문서/콘텐츠/대용량/참고자료 중심
6. GitHub는 구조 설계/PRD/README/프롬프트/코드/자동화/운영문서 중심
7. 로컬/Drive는 한글 중심 명명
8. GitHub는 영문 또는 혼합 명명 허용
9. 설명 문서는 한글 작성
10. 민감정보/API 키/인증 파일은 GitHub 업로드 금지

## 4. 저장 위치별 역할

### 4.1 로컬

- 원본 보존, 실행 환경, 최근 자료 집결
- 장기 보존 원본 기준 저장소

### 4.2 Google Drive

- 공유/협업 문서, 대용량 파일, 참고자료 보관
- 회사/개인/콘텐츠 자료 분리 운영

### 4.3 GitHub

- 작업본부(기준 문서 + 코드 + 자동화 + 이력)
- 버전 추적 및 운영 기준의 단일 출처(SSOT)

## 5. 범위

포함:
- docs 중심 기준 문서 체계 수립
- 자산 분류/저장 위치/정리 원칙 문서화
- 점진적 구조 확장 기준 정의

제외:
- 승인 없는 대량 삭제
- 민감정보 업로드
- 근거 없는 대규모 구조 변경

## 6. 초기 구조 제안 (v1)

```text
my-workbench/
  README.md
  docs/
    README.md
    PRD.md
    정리원칙.md
    자산분류기준.md
    저장위치기준.md
    운영절차.md
    후속구조확장.md
    후속작업기준.md
```

설명:
- 초기에는 `docs`에 기준을 집중해 운영 복잡도를 최소화한다.
- 실행 코드는 필요가 확인될 때 단계적으로 추가한다.

## 7. 점진 확장 기준 (게이트)

### Gate A: 문서 안정화

- 기준 문서 4종(PRD/정리원칙/자산분류기준/저장위치기준) 정합성 확보

### Gate B: 인벤토리 기반 운영

- 최근 3개월/장기 보존 태깅 완료
- 상태값(KEEP/MERGE/MOVE/ARCHIVE/DELETE_CANDIDATE) 부여

### Gate C: 폴더 확장

- 반복 작업 3회 이상 또는 대상 파일 5개 이상일 때 신규 폴더 추가
- 확장 후보: `prompts/`, `templates/`, `workflows/`, `automation/`, `apps/`

### Gate D: 운영 고도화

- 주간/월간/분기 점검 루틴 정착
- 자동화/코드 자산을 운영 절차에 편입

## 8. 기능 요구사항 (FR)

- FR-1: 자산 분류 체계 정의
- FR-2: 최근 3개월 자료 점검 절차 정의
- FR-3: 저장 위치 결정 규칙 정의
- FR-4: GitHub 반영/제외 기준 정의
- FR-5: 후속 구조 확장 게이트 정의

## 9. 비기능 요구사항 (NFR)

- NFR-1: 안전성(삭제 전 검토/백업 확인)
- NFR-2: 추적성(커밋 및 문서 로그)
- NFR-3: 일관성(명명/경로 규칙)
- NFR-4: 보안성(민감정보 차단)
- NFR-5: 유지관리성(점진 확장)

## 10. 성공 기준

1. docs 중심 기준 문서 체계가 완성됨
2. 최근 자료와 장기 보존 자료의 판정 기준이 운영 가능함
3. 위치별 역할 분리가 문서와 실제 운영에 반영됨
4. 후속 확장 시점과 조건이 명확함
