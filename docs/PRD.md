# PRD: my-workbench

## 1. 프로젝트 개요

my-workbench는 개인 프로젝트와 회사 프로젝트를 포함한 디지털 자산을 통합 관리하는 작업본부 저장소다. 이 저장소는 코드만 관리하는 공간이 아니라, 기획/문서/프롬프트/코드/자동화/운영 원칙을 함께 버전 관리하는 운영체계로 사용한다.

## 2. 목적

1. 개인/회사 디지털 자산 재정비
2. 로컬, Google Drive, GitHub 역할 분리
3. 장기 보존 자료의 안정적 유지
4. 최근 3개월 자료의 점검/분류/통합
5. 유지할 개발 자산 선별
6. 구조/코드/프롬프트/자동화 문서의 버전 관리
7. Google Drive 아카이브 체계화
8. 민감정보 보호
9. 향후 PRD에도 재사용 가능한 정리 기반 확보

## 3. 핵심 문제

- 자료가 로컬/Drive/GitHub/도구에 분산됨
- 장기 보존 vs 최근 작업물 구분 기준이 약함
- 코드/문서/프롬프트/자동화 파일이 혼재됨
- 유지할 자산 선별 기준이 모호함
- 최근 생성 파일 누적으로 구조가 흐려짐
- 민감정보 외부 노출 위험 존재

## 4. 운영 철학

1. 저장소는 프로젝트 본부다.
2. 자료는 삭제 전에 판정한다.
3. 최근 자료는 현재 흐름으로 통합한다.
4. 장기 자산은 로컬에서 안정적으로 보존한다.
5. 설명은 한글 중심, 개발 경로는 안정성 우선으로 운영한다.

## 5. 저장 위치별 역할

### 5-1. 로컬 컴퓨터

- 실제 작업/실행 환경
- 장기 보존 자료 저장
- 원본 파일 관리
- 최근 생성 자료 1차 집결
- 최종 결과물 보관

장기 보존 예시:
- 사진자료
- 오래 보관한 파일
- 중요 원본
- 장기 가치 개인 기록
- 과거 프로젝트 참고 자산

최근 자료(3개월 미만) 처리:
- 유지
- 통합
- 이동
- 보관
- 삭제 후보 지정

### 5-2. Google Drive

- 대용량 파일 저장
- 회사 문서/자료 보관
- 콘텐츠 자료 보관
- 원본문서/참고자료 보관
- 공유 문서 관리

운영 원칙:
- 프로젝트/성격별 폴더 분리
- 최소 권한 공유
- 회사/개인/콘텐츠 자료 분리

### 5-3. GitHub

- 구조 설계, 코드, 프롬프트, 문서, 자동화 자산의 실행 본부
- 변경 이력 관리

GitHub 반영 대상:
- 구조 설계 문서
- PRD
- README
- 프롬프트
- 템플릿
- 코드
- 자동화 스크립트
- 운영 기준 문서
- 업무 흐름 문서

GitHub 제외 대상:
- 개인정보, 계좌정보, 신분증 사본
- 비밀번호, API 키, 인증 파일
- 회사 민감 원본자료
- 외부 공개 위험 비공개 자료

## 6. 폴더/파일명 원칙

- 로컬/Google Drive: 한글 중심
- GitHub: 개발 안정성을 위해 영문 또는 혼합 허용
- 의미 설명 문서는 한글 유지

## 7. 범위

포함:
- 운영 기준 수립
- 저장 위치 역할 설계
- 분류/통합 기준 설계
- 최근 3개월 자료 관리 기준
- 장기 보존 기준 수립
- 저장소 구조 설계
- PRD 및 운영 문서 작성

제외:
- 사용자 승인 없는 대량 삭제
- 민감자료 무단 업로드
- 근거 없는 대규모 이동
- 운영 레포 파괴적 변경

## 8. 기능 요구사항 (FR)

- FR-1: 자산 분류 기준
- FR-2: 최근 3개월 자료 검토 질문 기반 판정
- FR-3: 통합 기준 적용
- FR-4: GitHub 반영 기준
- FR-5: Google Drive 정리 축
- FR-6: 삭제 후보 보고서 작성

## 9. 비기능 요구사항 (NFR)

- NFR-1: 안전성 (백업/대체본 확인)
- NFR-2: 추적 가능성 (커밋 이력)
- NFR-3: 일관성 (구조/명명)
- NFR-4: 보안성 (민감정보 차단)
- NFR-5: 유지관리성 (재사용 가능한 기준)
- NFR-6: 이해가능성 (한글 문서)

## 10. 보안 원칙
