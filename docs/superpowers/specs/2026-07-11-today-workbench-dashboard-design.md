# 오늘의 업무 대시보드 설계

## 1. 목적

코딩을 모르는 사용자가 프로그램을 열었을 때, 복잡한 프로젝트 관리 용어를 배우지 않고도 지금 해야 할 일과 다음 행동을 바로 확인할 수 있는 개인 업무 홈페이지를 만든다.

이 기능은 JIRA를 대체하지 않는다. JIRA는 팀의 공식 개발 이슈를 관리하고, my-work-bench는 개인의 오늘 업무, 메모, 다음 행동을 한 화면에서 운영한다. 첫 버전에서는 JIRA 이슈 링크만 연결한다.

## 2. 사용자 경험 목표

- 첫 화면을 업무 앱이면서도 홈페이지처럼 느끼게 한다.
- 가장 중요한 행동인 `할 일 추가`를 화면에서 즉시 찾을 수 있게 한다.
- 입력은 제목 하나로 시작하고, 상세 정보는 필요할 때만 연다.
- 상태 이름을 기술 용어 대신 쉬운 한국어로 표시한다.
- 완료되지 않은 업무 전체를 기본으로 보여준다.
- 완료 업무는 화면을 복잡하게 만들지 않도록 접어서 제공한다.
- 기존 사용자 데이터와 문서, 작업 중인 변경사항을 삭제하거나 되돌리지 않는다.

## 3. 첫 화면 구성

### 3.1 헤더

- 서비스 이름: `my-work-bench`
- 화면 제목: `오늘의 업무`
- 현재 날짜와 짧은 안내 문구
- 화면의 핵심 행동인 `할 일 추가` 버튼

### 3.2 요약 영역

카드 4개를 사용한다.

- 해야 할 일
- 하고 있는 일
- 막힌 일
- 완료한 일

카드는 숫자와 짧은 설명을 함께 표시하고, 클릭하면 해당 상태의 업무 목록으로 이동하거나 필터링한다.

### 3.3 업무 영역

미완료 업무 전체를 다음 순서로 표시한다.

1. 마감일이 지난 업무
2. 우선순위가 높은 업무
3. 오래된 업무
4. 최근 추가된 업무

업무 상태는 다음 네 가지를 사용한다.

- `해야 할 일` (`todo`)
- `하고 있는 일` (`in_progress`)
- `막힌 일` (`blocked`)
- `완료` (`done`)

각 업무 카드에는 제목, 상태, 프로젝트명, JIRA 연결 여부를 표시한다. 가능한 동작은 `완료`, `진행 중`, `막힘`, `수정`, `삭제`로 제한하고, 버튼에 아이콘만 사용하지 않고 한국어 텍스트도 함께 표시한다.

### 3.4 완료 업무 영역

완료 업무는 기본적으로 접힌 상태로 둔다. `완료한 일 보기`를 누르면 최근 완료 업무를 펼쳐 보여준다.

### 3.5 빈 상태

업무가 하나도 없을 때는 빈 화면 대신 다음 행동을 안내한다.

> 아직 등록한 일이 없습니다. 오늘 해야 할 일 하나를 적어보세요.

큰 `첫 할 일 추가하기` 버튼도 함께 표시한다.

## 4. 할 일 추가 및 수정

### 4.1 빠른 추가

기본 입력은 제목 하나다. 예를 들어 `JIRA 로그인 오류 이슈 확인`을 입력하고 저장하면 다음 기본값을 사용한다.

- 상태: `todo`
- 우선순위: `normal`
- 마감일: 없음
- 진행률: 0
- 생성일과 수정일: 현재 시각

제목이 비어 있으면 저장하지 않고 `할 일 제목을 적어주세요.`라고 안내한다.

### 4.2 상세 수정

수정 화면에서만 다음 필드를 제공한다.

- 제목
- 상태
- 마감일
- 우선순위
- 프로젝트명
- JIRA 링크
- 메모

초기 화면에서는 상세 필드를 숨겨 입력 부담을 줄인다.

## 5. 데이터 모델

기존 `DashboardTask` 및 localStorage 기반 프로젝트 저장 패턴과 호환되도록 한다. 필요한 업무 필드는 다음과 같다.

```text
id: string
title: string
status: "todo" | "in_progress" | "blocked" | "done"
priority: "low" | "normal" | "high"
deadline: string
projectName: string
jiraUrl: string
note: string
progress: number
createdAt: string
updatedAt: string
```

첫 버전의 웹 저장소는 localStorage를 사용한다. 저장 키는 기존 키와 충돌하지 않도록 별도로 관리한다. 향후 JSON/Markdown 내보내기와 JIRA 동기화를 추가할 수 있도록 저장 로직을 UI 컴포넌트와 분리한다.

## 6. 시각 디자인 방향

- 밝은 배경과 진한 본문 색상으로 가독성을 우선한다.
- 첫 화면에는 넓은 여백, 둥근 카드, 얕은 그림자를 사용한다.
- 업무 상태는 색상만으로 구분하지 않고 텍스트 배지를 함께 표시한다.
- `할 일 추가`는 가장 눈에 띄는 강조색을 사용한다.
- 긴 설명과 전문 용어를 줄이고 짧은 한국어 문장을 사용한다.
- 모바일 화면에서는 요약 카드를 2열 또는 1열로 재배치한다.
- 데스크톱에서는 요약 카드와 업무 목록의 계층이 분명하게 보이도록 한다.

## 7. 사용자 흐름

```text
홈페이지 열기
  -> 미완료 업무와 요약 확인
  -> 할 일 추가 버튼 클릭
  -> 제목 입력
  -> 해야 할 일 목록에 추가
  -> 진행 중/막힘/완료 상태 변경
  -> 필요할 때 상세 정보와 JIRA 링크 수정
```

## 8. 오류 및 안전 처리

- 제목이 비어 있으면 저장하지 않는다.
- 삭제 전 확인을 받는다.
- 잘못된 JIRA 링크라도 업무 자체는 저장한다.
- localStorage 데이터가 손상되면 빈 목록으로 안전하게 시작하고 오류를 사용자에게 과도하게 노출하지 않는다.
- 기존 프로젝트 데이터와 저장 키는 유지한다.
- 실제 JIRA API, 외부 서버, 인증 정보는 첫 버전에서 사용하지 않는다.

## 9. 구현 범위

포함:

- 오늘의 업무 홈페이지형 웹 화면
- 할 일 추가, 수정, 삭제
- 상태 변경
- 완료 업무 접기/펼치기
- 프로젝트명과 JIRA 링크 저장
- localStorage 저장 및 새로고침 후 복원
- 반응형 스타일
- 웹 빌드 검증

제외:

- 실제 JIRA API 연동
- AI 자연어 업무 생성
- Google Drive 동기화
- 로그인, 다중 사용자, 팀 협업
- 캘린더 및 알림 연동

## 10. 검증 기준

- 사용자가 첫 화면에서 5초 안에 `할 일 추가` 위치를 찾을 수 있다.
- 제목만으로 새 업무를 추가할 수 있다.
- 새로고침 후 업무가 유지된다.
- 업무 상태를 네 가지 상태로 변경할 수 있다.
- 완료 업무가 기본 업무 목록을 복잡하게 만들지 않는다.
- JIRA 링크가 저장되고 다시 열 수 있다.
- 모바일과 데스크톱 화면에서 주요 버튼과 목록이 사용 가능하다.
- `npm run build:web`가 성공한다.
