# Threads AI 소식 실험 노트

## 승인된 목표

Threads 게시물과 기사를 읽고 내 관심·업무에 맞는 작은 실험으로 바꾸면서 AI 활용을 배운다. 사용자는 추진계획 검토보다 소식 실험 노트를 선택했고, 유료 OpenAI API 대신 무료 API와 GitHub Pages 배포를 요청했다.

## 역할과 흐름

planning-copilot의 계획서 작성 기능을 복제하지 않는다. my-work-bench는 소식 원문, 주장·검증 근거, 적용할 업무, 실험의 성공 기준, 실행 결과·학습을 보관한다. 입력 → 내 기준으로 AI 추천 → 실험 선택 → 결과 기록 → 다음 행동 순서다. 기존 업무 대시보드와 도구는 별도 탭으로 보존한다.

## 구현 선택과 영향

- React/Vite, 기존 PDF 추출 라이브러리를 재사용한다. 새 의존성과 서버를 추가하지 않는다.
- 링크만으로 Threads를 읽었다고 주장하지 않는다. 사용자가 원문을 붙여넣거나 TXT/MD/PDF를 읽고 공식 출처를 기록한다. 스캔 PDF는 OCR이 필요함을 안내한다.
- OpenRouter PKCE 계정 연결 및 개인 키의 임시 입력을 지원한다. 키는 앱 메모리에만 두고 저장소·백업·GitHub에 저장하지 않는다. PKCE 검증 정보만 일시적으로 sessionStorage에 두고 콜백 후 지운다.
- 공개 모델 목록에서 무료 가격을 확인하고 `openrouter/free`만 호출한다. 공급자 가격 상한을 0으로 지정하고 유료 모델·검색·자동 재시도를 사용하지 않는다. 한도 초과·무료 서비스 중단은 명시적 오류로 처리한다.
- 외부 전송 전 동의를 받고 실제 모델명·AI 제안 여부를 표시한다. AI 답변을 공식 사실 확인으로 취급하지 않는다.
- 기록은 별도 localStorage 키에 보관한다. 자동 저장, JSON 백업·검증된 병합 복원, Markdown 내보내기를 제공한다. API 키는 명시적 허용 필드 밖이라 백업에서 제외된다.
- GitHub Pages는 공개 정적 화면만 배포한다. 개인 기록은 사용자의 브라우저에 남으며 기기 간 자동 동기화는 없다. base 경로를 빌드 환경변수로 지정하여 기존 Netlify·로컬 실행도 유지한다.

## 완료 기준

원문 기록·편집, 출처와 검증 상태, 관심과 목표 설정, 무료 AI 요청과 실패 처리, 추천에서 실험 만들기, 상태·시간·수정 횟수·성과·학습 기록, 새로고침 복원, 백업 복원, 모바일 사용을 검증한다. 테스트·전체 빌드와 Pages 경로 빌드를 통과한 코드를 GitHub PR로 반영하고 실제 Pages 주소 응답을 확인한다. 계정 로그인이 필요한 라이브 AI 검증은 모의 검증과 구분해 보고한다.
