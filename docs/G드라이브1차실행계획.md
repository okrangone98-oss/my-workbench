# G드라이브 1차 실행 계획

## 1. 목적

로컬 `G:\`를 장기 보존, 최근 3개월 검토, 진행 중 프로젝트 기준으로 1차 분류하고, 무리한 이동이나 삭제 없이 운영 가능한 상태로 만든다.

## 2. 적용 범위

- `G:\` 내 개인/회사 작업 자산
- 최근 3개월 내 생성 또는 수정된 자료
- 장기 보존 가치가 높은 원본 자료

제외:
- 시스템 폴더
- 프로그램 설치 폴더
- 즉시 삭제가 필요한 것으로 확정되지 않은 자료

## 3. 목표 산출물

1. 자산 인벤토리 파일 1개 이상
2. 최근 3개월 점검표 1개 이상
3. 삭제 후보 보고서 1개 이상
4. 주간 점검 로그 1개 이상

## 4. 1차 분류 기준 경로

- `G:\장기보관자료\`
- `G:\최근3개월검토\`
- `G:\진행중프로젝트\`

실제 이동 전 원칙:
- 원본 위치를 먼저 기록한다.
- 민감정보 가능성은 GitHub 문서에 내용 자체를 적지 않고 상태만 기록한다.
- 삭제는 하지 않고 `DELETE_CANDIDATE`로만 등록한다.

## 5. 실행 순서

### Step 1. 상위 폴더 목록화

- `G:\` 바로 아래 폴더를 우선 수집한다.
- 개인/회사/임시/보관 성격을 1차 태깅한다.

### Step 2. 최근 자료 식별

- 최근 90일 내 생성/수정 자료를 선별한다.
- `최근3개월점검표` 기준으로 판정한다.

### Step 3. 장기 보존 후보 식별

- 사진 원본, 중요 문서 원본, 오래 보관한 참조 자료를 추린다.
- `장기보관자료` 기준 폴더로 이동 후보를 지정한다.

### Step 4. 진행 중 프로젝트 집계

- 현재 유지 중인 프로젝트별 자료를 묶는다.
- 프로젝트 단위 기준본과 중복본을 구분한다.

### Step 5. 보고서 및 로그 작성

- 삭제 후보는 보고서로 분리한다.
- 주간 단위 진행상황을 로그로 남긴다.

## 6. 판정 우선순위

1. 민감정보 포함 여부
2. 장기 보존 필요성
3. 현재 프로젝트 연관성
4. 최근 3개월 생성/수정 여부
5. 중복 여부
6. 백업 또는 대체본 존재 여부

## 7. 완료 조건

- `G:\` 상위 폴더가 인벤토리에 등록됨
- 최근 자료가 최소 1차 판정됨
- 삭제 후보가 별도 보고서로 분리됨
- 다음 주 점검 범위가 정의됨
